# ALLEGRO Project Rules

- Keep the approved centered editorial hero, tone, and visual hierarchy.
- Follow `ENGINEERING_STANDARD.md`: small, focused files, strict TypeScript, accessible interactions.
- Feature modules own their components, data and local CSS. Shared components must be genuinely reused.
- Keep this MVP static; no API, persistence, auth, repository or service layer without requirements.
- Prefer native Web APIs and simple CSS to new UI/animation dependencies.
- Preserve reduced-motion behavior and visible content without JavaScript.
- Never invent ALLEGRO phone numbers, stock availability, prices or operational claims.
- Before shipping, run lint, typecheck, tests, build, and responsive visual checks.
